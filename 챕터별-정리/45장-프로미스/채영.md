# 45장 프로미스

콜백 패턴의 단점을 개선하려고 등장한 프로미스 (ES6에 도입)

> 바동기 함수는 함수내의 비동기 이벤트만 등록하고 동기 코드 실행이 끝나면 종료된다. 이때 등록된 비동기 이벤트는 비동기 함수가 종료된 후에 실행된다.

```typescript
const get = url => {
    const xhr = new XMLHttprequest();
    xhr.open('GET', url);
    xhr.send();
    xhr.onload = () => {
        if(xht.status === 200){
            return JSON.parse(xhr.response);
        }
    console.log(`${xhr.status} ${xhr.statusText}`);
    }
}

const response = get('https://testapi.com/posts/1')
console.log(response) //undefined
```

비동기 함수인 get은 onload 이벤트 핸들러의 반환값을 캐치하지 못해 `response`호출에서 undefined가 출력되는 것을 확인할 수 있다.

그럼 응답 값을 반환하기 위해 상위 슼프에 넣으면? 그래도 undefined가 출력된다.
이렇게 처리 순서가 보장되지 않는다는 점은 실행컨텍스트를 통해 생각해볼 수 있다.
- 비동기 함수는 등록된 이벤트 핸들러가 즉시 실행되는 것이 아닌 이벤트가 발생하면 일단 태스트 큐에 저장되어 대기하다가, 콜 스택이 비면 이벤트 루프에 의해 콜 스택으로 푸시되어 실행된다. 즉, 동기함수들이 다 실행되어 콜 스택이 빈 시점에 태스크큐에서 콜스택에 푸시되어 이벤트 핸들러가 실행된다.
- 비동기 함수의 처리 결과와 같은 후속처리는 비동기 함수 내부에서 처리 해야한다.

- 비동기 처리 결과에 대한 후속 처리를 수행하기 위해 콜백함수를 전달하는 것이 일반적이다.

```typescript
const get = ( url, successCallback, failureCallback ) => {
    const xhr = new XMLHttprequest();
    xhr.open('GET', url);
    xhr.send();
    xhr.onload = () => {
        if(xht.status === 200){
            successCallback(JSON.parse(xhr.response));
        } else {
            failureCallback(xhr.status);
        }
    }
}

get( 'https://testapi.com/posts/1', console.log, console.error )
```


## 비동기 함수 후속처리를 콜백 함수로 했을 때의 문제점
- 콜백 함수를 통해 비동기 후속 처리를 하고 또 다시  콜백 함수로 후속 처리를 해야한다면 콜백 함수 호출이 중첩되어 복잡도가 높아지는 현상이 발생하는 것을 콜백헬Callback Hell이라고 한다. 
- 에러 처리를 하기위해 try catch finally문을 활용했을 때 비동기 함수일 경우 `catch (e) { ... }` 헤어 에러를 캐치되지 않는다. 이 때 에러는 호출자 방향으로 전파된다. 이렇게 에러처리가 곤란하고 콜백헬과 같은 문제를 극복하기 위해 프로미스가 도입되었다.
